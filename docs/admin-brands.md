# Админка брендов и витринный слой

Модуль `packages/backend/src/admin/` + страница `packages/backend/public/admin/index.html`.
Миграция: `packages/backend/migrations/004_site_brands.sql` (автоприменяется при старте, как 002/003).

## Зачем

В реальной выгрузке 1С бренда нет: позиции приходят SKU без родительских товаров, а бренд «зашит» в название
(см. dev-log). При этом сайту нужны: «Топ бренды» с фото и логотипом, списки «Все бренды» по разделам
(мужское/женское), страницы брендов. Всё это — редакционные данные сайта, поэтому живут в **отдельном слое**
(`site_*`), который обмен с 1С не читает и не перезаписывает. Staging-таблицы 001–003 админка только читает.

## Модель данных

| Таблица                 | Что хранит                                                                        |
| ----------------------- | --------------------------------------------------------------------------------- |
| `site_brands`           | бренд: адрес (`slug`), название на сайте, имена файлов фото и логотипа            |
| `site_brand_aliases`    | написания бренда в названиях товаров (нормализованные, глобально уникальные)      |
| `site_brand_placements` | в каком разделе (`men`/`women`) бренд показан, входит ли в топ и в каком порядке  |
| `site_model_brand`      | бренд модели; `origin = auto` (найден по алиасам) или `manual` (назначил человек) |

Модель = Ид товара до `#` (то есть `product_variants.product_source_id`). Название модели берётся у товара,
если он пришёл, иначе у SKU. Между `site_*` и staging нет FK: staging перезаписывается обменом.

## Как бренд находится у модели

1. Название бренда и его алиасы приводятся к виду «нижний регистр, без диакритики, знаки → пробел»
   (`Annette Görtz` → `annette gortz`, `MAX&MOI` → `max moi`).
2. Ищем как целые слова в нормализованном названии модели.
3. Побеждает самое длинное совпадение (`Persona by Marina Rinaldi` против `Marina Rinaldi`);
   при равных совпадениях у разных брендов модель остаётся без бренда — решает оператор.
4. Ручные привязки (`manual`) пересчёт не трогает.

Пересчёт запускается: при старте, при создании бренда и смене названия/алиасов, по кнопке «Пересчитать» в админке.
**Открытый вопрос:** после каждого обмена пересчёт пока ручной (кнопка). Если нужно автоматически — вызвать
`BrandService.recompute()` из конца `import-runner` (одна строка, но это уже правка кода обмена — решает Ян).

Вкладка «Без бренда» показывает модели без привязки и самые частые начала названий — по клику заводится
бренд с этим названием.

## Публичное API для сайта (без авторизации, CORS `*`, кеш 60 с)

```
GET /api/brands?gender=men|women
→ { "gender": "men",
    "top": [{ "name", "slug", "photo", "logo" }],   // по порядку плиток
    "all": [{ "name", "slug" }] }                    // по алфавиту

GET /api/brands/:slug/models?limit=24&offset=0
→ { "brand": { "name", "slug" }, "total": 17,
    "items": [{ "id", "name", "skus", "photo" }] }

GET /uploads/:file   — фото и логотипы брендов (имя = 16 hex + расширение)
```

`photo`/`logo` — абсолютные URL при заданном `PUBLIC_BASE_URL`, иначе относительные (`/uploads/…`).
Фото моделей собираются из путей выгрузки 1С (`import_files/…`) как `IMAGES_BASE_URL + путь`; по умолчанию
`PUBLIC_BASE_URL/images/` — под план A2 (Caddy `/images/*`). Пока A2 нет, эти фото по ссылке не откроются.
Цен и остатков в API нет — ждём `offers.xml` (блокер A1).

Страница `brands.html` сайта уже умеет читать этот формат (`loadBrandsFromApi`): при недоступном API
показываются зашитые в страницу списки.

## Админка

`https://<домен>/admin` — Basic-авторизация (`ADMIN_LOGIN`/`ADMIN_PASSWORD`). Вкладки: обзор, бренды
(карточка: название, написания, разделы, топ, фото, логотип, адрес, удаление), топ-бренды (порядок), без бренда,
обмен с 1С (последние загрузки и журнал запросов). Кнопка «Загрузить список брендов сайта» заводит стартовый
словарь (51 бренд, топы по разделам) — идемпотентно, существующие бренды не меняет.

Безопасность:

- пустые логин/пароль = админка выключена (публичное API при этом работает);
- сравнение учётных данных за постоянное время; не более 10 неудач за 10 минут с адреса, затем 429
  (за Caddy включён `TRUST_PROXY=1`, иначе все запросы были бы «с одного адреса»);
- изменения требуют заголовка `X-FA-Admin: 1` (защита от CSRF при Basic-авторизации);
- загрузка: сырое тело ≤ 8 МБ, тип определяется по сигнатуре (JPEG/PNG/WebP/AVIF; SVG не принимаем),
  имя файла генерируется сервером, отдаются и удаляются только свои файлы;
- страница отдаётся с CSP и `frame-ancestors 'none'`.

Дополнительно можно закрыть `/admin*` в `deploy/Caddyfile` по IP (`@admin path /admin*` + `remote_ip`).

## Переменные окружения

| Переменная          | По умолчанию | Что делает                                                     |
| ------------------- | ------------ | -------------------------------------------------------------- |
| `ADMIN_LOGIN`       | пусто        | логин админки; пусто — админка выключена                       |
| `ADMIN_PASSWORD`    | пусто        | пароль админки (генерировать на сервере)                       |
| `ADMIN_UPLOADS_DIR` | `uploads`    | каталог фото/логотипов (в Docker — volume `uploads`)           |
| `PUBLIC_BASE_URL`   | пусто        | публичный адрес бэкенда для абсолютных ссылок в API            |
| `IMAGES_BASE_URL`   | пусто        | база ссылок на фото товаров; пусто = `PUBLIC_BASE_URL/images/` |
| `TRUST_PROXY`       | выкл.        | `1` — брать адрес клиента из `X-Forwarded-For` (задан в prod)  |

## Деплой

См. раздел 6 в `docs/deploy-fa-dev.md`. Новых зависимостей в `package.json` нет (загрузка файлов — сырым телом,
отдача — вручную), `package-lock.json` не меняется.

## Что не сделано / решить

  не зависит.
- Автопересчёт после обмена (см. выше).
- Бэкап: `deploy/backup-db.sh` покрывает БД; volume `uploads` (фото брендов) нужно бэкапить отдельно или перенести
  в общее медиа-хранилище вместе с A2.
- Алиасы стартового словаря — догадки о написаниях в 1С; уточнить по реальной выгрузке (вкладка «Без бренда»).
