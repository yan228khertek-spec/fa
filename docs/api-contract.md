Общие правила:

- Все публичные ответы — JSON, `Access-Control-Allow-Origin: *` (витрина и API на разных поддоменах).
- Кэш: `Cache-Control: public, max-age=30…60` на публичных ручках.
- Фото в ответах — абсолютные URL (`PUBLIC_BASE_URL` + путь), либо `null`.
- Числовые/строковые query-параметры санируются сервером (обрезка длины, клампинг пагинации); неизвестные значения игнорируются.
- Раздел (`category`) и вид изделия (`kind`) **вычисляются из названия товара 1С** (в выгрузке нет связи товар→категория), а не хранятся.

## Публичные ручки (витрина)

### `GET /api/brands?gender=men|women`

Бренды раздела: «Топ бренды» (плитки) и полный список.

- Query: `gender` — `men` или `women` (по умолчанию `women`; иное → `400`).
- Ответ `200`:

```json
{
  "gender": "women",
  "top": [
    {
      "name": "Marina Rinaldi",
      "slug": "marina-rinaldi",
      "photo": "https://…/uploads/….jpg",
      "logo": "https://…/uploads/….png"
    }
  ],
  "all": [{ "name": "…", "slug": "…" }]
}
```

`photo`/`logo` могут быть `null`. `top` отсортирован по порядку плиток, `all` — по имени.

### `GET /api/brands/:slug/models`

Карточки бренда с фасетами (для страницы бренда).

- Path: `slug` — адрес бренда. Нет бренда → `404 {error}`.
- Query: `category` (≤40), `kind` (≤60), `limit` (1…100, деф. 24), `offset` (≥0).
- Ответ `200`:

```json
{
  "brand": { "name": "…", "slug": "…" },
  "total": 42,
  "facets": {
    "categories": [{ "name": "Одежда", "count": 30 }],
    "kinds": [{ "name": "Джемпер", "count": 8 }]
  },
  "items": [/* см. элемент листинга ниже */]
}
```

### `GET /api/home`

Блоки главной: бренды с флагом «Показывать на главной» и их последние опубликованные карточки.

- Ответ `200`:

```json
{ "brands": [{ "name": "…", "slug": "…", "total": 12, "items": [/* элемент листинга */] }] }
```

Бренд без видимых карточек в блок не попадает. До 3 брендов, до 4 карточек в каждом.

### `GET /api/cards?category=&kind=&limit=&offset=`

Листинг витрины (только видимые карточки).

- Query: `category` (≤40), `kind` (≤60), `limit` (1…100, деф. 24), `offset` (≥0).
- Ответ `200`:

```json
{
  "total": 120,
  "facets": {
    "categories": [{ "name": "Одежда", "count": 80 }],
    "kinds": [{ "name": "Платье", "count": 15 }]
  },
  "items": [/* элемент листинга */]
}
```

**Элемент листинга (`items[]`)** — единый для `/api/cards`, `/api/brands/:slug/models`, `/api/home`:

```json
{
  "id": 17,
  "modelId": "<GUID товара 1С>",
  "title": "Платье Pinko чёрное",
  "brand": { "name": "Pinko", "slug": "pinko" },
  "photo": "https://…/uploads/….jpg",
  "price": 18990,
  "inStock": true,
  "category": "Одежда",
  "kind": "Платье"
}
```

`brand`, `photo`, `price`, `inStock` могут быть `null` (нет бренда / фото / цены / данных об остатке).

### `GET /api/cards/:id`

Карточка целиком (страница товара).

- Path: `id` — целое > 0. Не найдено / не видима → `404 {error}`.
- Ответ `200` — элемент листинга **плюс**:

```json
{
  "article": "PK-1234",
  "description": "…",
  "characteristics": [{ "name": "Состав", "value": "Шерсть 80%" }],
  "photos": ["https://…/uploads/a.jpg", "https://…/uploads/b.jpg"],
  "sizes": [
    { "id": "<GUID модели>#<GUID характеристики>", "size": "46", "color": "чёрный", "inStock": true, "price": 18990 }
  ]
}
```

`sizes[].id` (v1.2) — идентификатор SKU, который корзина передаёт в `POST /api/orders` как `variantId`. `sizes[].price` (v1.2) — цена именно этого SKU (тип «Розничные»), `null` — цены нет, такой размер не продаётся. Корзина показывает цену размера, а не цену модели из листинга.

### `GET /uploads/:file`

Фото и логотипы (загруженные в админке). Имя строго `^[a-f0-9]{16}\.(jpg|png|webp|avif)$`, иначе `404`. Заголовки: `Content-Type` по расширению, `X-Content-Type-Options: nosniff`, `Cache-Control: public, max-age=604800, immutable`.

### `GET /images/*`

Фото из выгрузки 1С (A2/M1). Отдаёт **Caddy** напрямую из тома `media`, минуя backend.

- Путь после `/images/` — значение `product_images_meta.path`, то есть относительный путь внутри выгрузки: `/images/import_files/ab/cd.jpg`.
- Только `GET` и `HEAD`; остальные методы — `405`.
- Отдаются **только картинки** (`jpg/jpeg/png/webp/avif/gif/bmp`); файл с любым другим расширением — `404`, даже если он лежит в томе: содержимое приходит из 1С, а `.html`/`.svg` исполнялся бы на origin API, где живут `/admin` и `/uploads`.
- Заголовки: `Cache-Control: public, max-age=86400`, `X-Content-Type-Options: nosniff`.
- Файл появляется после успешного `import.xml` (backend переносит `spool/unpacked/import_files` в хранилище) и **не удаляется** следующими выгрузками: старые URL не рвутся. `404` — фото в выгрузках не было.
- Базовый адрес для витрины — `IMAGES_BASE_URL`, по умолчанию `PUBLIC_BASE_URL + /images/`. Формула для карточки: URL фото = `https://1c-dev.avenuefashion.online/images/` + путь из колонки «Файлы фото».

Фото, загруженные в админке Ангелиной, живут отдельно — `/uploads/:file` (том `uploads`).

## Правило видимости карточки (A5)

Карточка попадает в публичную выдачу, только если: статус `published` **И** есть хотя бы одно фото **И** модель есть в staging 1С **И** (если остаток известен) остаток > 0. Иначе карточка скрыта (`draft` / `gone` / `no-photo` / `no-stock`), но **не удаляется**. Скрытие — правилом в API, не обменом.

## Заказы (F1) · v1.2 · Владу на согласование

Корзина живёт **на клиенте** (localStorage витрины); сервер видит заказ один раз — при оформлении. Онлайн-оплаты, выгрузки в 1С, статусов из 1С и личного кабинета в v1 нет; поля ответа под них уже есть и в v1 имеют значения по умолчанию.

Общие правила раздела:

- CORS как у остального публичного API: `Access-Control-Allow-Origin: *`. На `OPTIONS /api/orders` сервер отвечает `204` (разрешены `POST`, заголовки `Content-Type`, `Idempotency-Key`).
- Деньги — JSON-числа в рублях с копейками (`18990`, `499.5`). Валюта всегда `RUB`. Заказчик на УСН — цены **без НДС**.
- Ошибка — всегда `{"error": "<КОД>", "message": "<текст для человека>", …}`. Фронт ветвится по `error`, `message` можно показать как есть.
- **Сервер ничему из запроса не верит:** цену, остаток, видимость карточки, стоимость доставки и итог он пересчитывает сам. Цена из запроса нужна только чтобы заметить, что покупатель видел другую.

### `GET /api/checkout/config`

Настройки чекаута. Фронт берёт отсюда стоимость доставки и версии документов, **ничего из этого не зашивает в код**.

```json
{
  "ordersEnabled": true,
  "currency": "RUB",
  "delivery": {
    "methods": [
      { "id": "pickup", "title": "Самовывоз из магазина", "cost": 0, "address": null },
      { "id": "cdek", "title": "Доставка СДЭК", "cost": 500, "freeFrom": 20000 }
    ]
  },
  "payment": {
    "methods": [
      { "id": "on_receipt", "title": "Оплата при получении", "available": true },
      { "id": "online", "title": "Онлайн-оплата картой", "available": false }
    ]
  },
  "documents": {
    "offerVersion": "draft-2026-10",
    "pdPolicyVersion": "draft-2026-10",
    "marketingConsentVersion": "draft-2026-10"
  },
  "limits": { "maxItems": 30, "maxQuantity": 10 }
}
```

- `delivery.methods[cdek].cost` — фикс-тариф v1; `freeFrom` — сумма товаров, начиная с которой СДЭК бесплатно (`null` — порога нет). Самовывоз — всегда 0. ⚠️ **Обе цифры (500 ₽ и 20 000 ₽) с заказчиком НЕ согласованы** (20 000 взято с бегущей строки макета) и меняются через env сервера (`ORDER_CDEK_FEE`, `ORDER_FREE_DELIVERY_FROM`) без правки кода и контракта — поэтому фронт их и не зашивает.
- `pickup.address` — адрес магазина для самовывоза; `null`, пока заказчик не дал точный адрес (`ORDER_PICKUP_ADDRESS`).
- `payment.methods[online].available` — `false` до трека F4 (ЮKassa). Пока `false`, кнопку онлайн-оплаты не показывать.
- `documents.*Version` — версии оферты, политики ПД и текста согласия на рассылку. ⚠️ Сейчас черновые; финальные придут с юрдокументами (К3). Фронт рядом с чекбоксами ссылается на документ этой версии.
- `ordersEnabled: false` — приём заказов выключен на сервере: кнопку «Оформить» не показывать, `POST` ответит `503`.

### `POST /api/orders`

Оформить заказ (гостевой, без регистрации).

Заголовки:

- `Content-Type: application/json` (иначе `415`), тело не больше **32 КБ** (иначе `413`).
- `Idempotency-Key: <ключ>` — **обязателен**. Фронт генерирует `crypto.randomUUID()` **один раз при открытии чекаута** и шлёт тот же ключ при каждой повторной попытке (двойной клик, ретрай после обрыва сети). Новый ключ — только для нового заказа (после успеха или после правки корзины/формы). Формат: 16–128 символов `[A-Za-z0-9_-]`.

Тело:

```json
{
  "customer": { "name": "Анна Петрова", "phone": "8 (913) 123-45-67", "email": "Anna@Mail.ru" },
  "delivery": { "method": "cdek", "city": "Омск", "address": "ул. Ленина, 10, кв. 5", "pvzCode": null },
  "payment": { "method": "on_receipt" },
  "comment": "Позвоните за час",
  "items": [
    { "cardId": 17, "variantId": "<GUID модели>#<GUID характеристики>", "quantity": 1, "price": 18990 }
  ],
  "expectedTotal": 19490,
  "consents": { "personalData": true, "marketing": false }
}
```

| Поле | Правило |
|---|---|
| `customer.name` | обязательно, 2–100 символов |
| `customer.phone` | обязательно; российский номер в любом написании (`+7…`, `8…`, `7…`, 10 цифр, со скобками/пробелами/дефисами). Сервер приводит к `+7XXXXXXXXXX` — **это ключ будущего личного кабинета** (вход по коду на телефон). Иначе `INVALID_PHONE` |
| `customer.email` | **обязательно**, до 254 символов, приводится к нижнему регистру |
| `delivery.method` | `pickup` \| `cdek` |
| `delivery.city`, `delivery.address` | для `cdek` обязательны (2–100 и 5–300 символов; адрес — свободный текст «адрес или ПВЗ»); для `pickup` игнорируются |
| `delivery.pvzCode` | необязательно, до 50 символов `[A-Za-z0-9-]` — задел под виджет ПВЗ СДЭК |
| `payment.method` | `on_receipt` \| `online`; `online` в v1 → `PAYMENT_METHOD_UNAVAILABLE` |
| `comment` | необязательно, до 1000 символов |
| `items` | 1–30 строк; `cardId` — id карточки витрины; `variantId` — `sizes[].id` этой карточки; `quantity` — целое 1–10; `price` — цена размера, которую видел покупатель (`sizes[].price`). Один `variantId` — одна строка (количество объединяет фронт), иначе `DUPLICATE_ITEM` |
| `expectedTotal` | необязательно; итог, который видел покупатель. Разошёлся с серверным → `409 TOTAL_CHANGED` |
| `consents.personalData` | **обязательно `true`** — чекбокс согласия на обработку ПД (152-ФЗ), иначе `PD_CONSENT_REQUIRED` |
| `consents.marketing` | необязательно, по умолчанию `false`. **Отдельный** чекбокс согласия на рекламные рассылки, по умолчанию **снят**, на приём заказа не влияет. При `true` сервер записывает согласие (время, IP, версия текста) |

Неизвестные поля игнорируются и нигде не сохраняются.

Ответ `201` (создан) — **представление заказа**:

```json
{
  "number": "FA-48271593",
  "token": "<43 символа>",
  "createdAt": "2026-10-15T18:40:00.000Z",
  "status": "new",
  "paymentStatus": "unpaid",
  "paymentMethod": "on_receipt",
  "delivery": { "method": "cdek" },
  "currency": "RUB",
  "itemsTotal": 18990,
  "deliveryCost": 500,
  "bonusAmount": 0,
  "total": 19490,
  "items": [
    {
      "cardId": 17,
      "title": "Платье Pinko чёрное",
      "article": "PK-1234",
      "size": "46",
      "color": "чёрный",
      "price": 18990,
      "quantity": 1,
      "amount": 18990
    }
  ]
}
```

- `number` — номер для покупателя (`FA-` + 8 цифр), его показываем и диктуем по телефону. **В URL не используется.**
- `token` — неугадываемый токен заказа. Страница «Спасибо» — `thanks.html?order=<token>`, данные — `GET /api/orders/:token`. Токен = доступ к заказу: не логировать в аналитику, не показывать.
- `total = itemsTotal + deliveryCost − bonusAmount`. `bonusAmount` — списано бонусов программы лояльности; **в v1 всегда `0`**, но строку «Списано бонусов» в составе заказа верстать сразу (показывать при `bonusAmount > 0`).
- `items[].price/amount` — **снимок** на момент заказа: последующая смена цены в 1С заказ не меняет.
- В ответе **нет** имени, телефона, email и адреса — только то, что можно показать по ссылке.

Повтор с тем же `Idempotency-Key` и тем же телом → `200` и **тот же** заказ (тот же `number` и `token`), второй заказ не создаётся; заголовок `Idempotent-Replayed: true`. Повтор срабатывает и после того, как товар закончился: заказ уже создан.

### `GET /api/orders/:token`

Заказ для страницы «Спасибо». Ответ `200` — представление заказа как выше, **без поля `token`**. `Cache-Control: no-store`. Нет такого токена → `404 ORDER_NOT_FOUND`.

### Коды ошибок

| HTTP | `error` | Когда | Что делать фронту |
|---|---|---|---|
| 400 | `INVALID_JSON` | тело не JSON / пустое | баг фронта |
| 400 | `IDEMPOTENCY_KEY_REQUIRED` | нет заголовка или неверный формат | баг фронта |
| 413 | `PAYLOAD_TOO_LARGE` | тело > 32 КБ | баг фронта |
| 415 | `UNSUPPORTED_MEDIA_TYPE` | не `application/json` | баг фронта |
| 422 | `VALIDATION_ERROR` | поля формы; `fields: [{ "field": "customer.phone", "code": "INVALID_PHONE" }]` | подсветить поля |
| 422 | `PAYMENT_METHOD_UNAVAILABLE` | `online` до F4 | убрать онлайн-оплату |
| 409 | `ITEMS_UNAVAILABLE` | часть позиций нельзя продать — см. ниже | обновить корзину |
| 409 | `TOTAL_CHANGED` | итог разошёлся с `expectedTotal`; в ответе актуальные `itemsTotal`, `deliveryCost`, `bonusAmount`, `total` | показать новый итог, попросить подтвердить |
| 409 | `IDEMPOTENCY_KEY_REUSED` | тот же ключ, но другое тело | баг фронта: новый заказ = новый ключ |
| 429 | `RATE_LIMITED` | > 20 попыток оформления за 10 мин с одного IP; заголовок `Retry-After` (сек) | «Слишком много попыток, попробуйте позже» |
| 503 | `ORDERS_DISABLED` | приём заказов выключен | «Оформление временно недоступно» |
| 500 | `INTERNAL_ERROR` | сбой сервера; заказ **не** создан | можно повторить с тем же ключом |

Коды полей в `VALIDATION_ERROR`: `REQUIRED`, `INVALID_TYPE`, `TOO_SHORT`, `TOO_LONG`, `INVALID_FORMAT`, `INVALID_PHONE`, `INVALID_EMAIL`, `INVALID_VALUE`, `PD_CONSENT_REQUIRED`, `TOO_MANY_ITEMS`, `INVALID_QUANTITY`, `DUPLICATE_ITEM`. Сервер возвращает все найденные ошибки разом.

### Краевые состояния позиций (`409 ITEMS_UNAVAILABLE`)

Заказ **не создаётся целиком**, если хотя бы одна позиция не проходит проверку; сервер перечисляет все проблемные строки:

```json
{
  "error": "ITEMS_UNAVAILABLE",
  "message": "Некоторые товары нельзя заказать",
  "items": [
    { "index": 0, "cardId": 17, "variantId": "…", "code": "NO_PRICE" },
    { "index": 2, "cardId": 21, "variantId": "…", "code": "INSUFFICIENT_STOCK", "available": 1 },
    { "index": 3, "cardId": 30, "variantId": "…", "code": "PRICE_CHANGED", "price": 15990 }
  ]
}
```

| `code` | Что случилось | UX |
|---|---|---|
| `CARD_NOT_AVAILABLE` | карточки нет, она снята с публикации или скрыта правилом A5 (товар исчез из 1С / нет остатка ни в одном размере) — «позиция исчезла» | «Товар больше недоступен», убрать из корзины |
| `VARIANT_NOT_FOUND` | такого размера у карточки больше нет | убрать строку |
| `NO_PRICE` | у размера нет цены в 1С. ⚠️ Это **частый** случай на текущих данных (у большинства SKU каталога нет предложений) — фронт должен его переживать | «Нет в продаже», убрать строку |
| `OUT_OF_STOCK` | остатка нет (или он неизвестен — без данных об остатке не продаём) | «Нет в наличии», убрать строку |
| `INSUFFICIENT_STOCK` | остатка меньше, чем `quantity`; `available` — сколько есть | уменьшить количество до `available` |
| `PRICE_CHANGED` | цена в 1С не та, что видел покупатель; `price` — актуальная | обновить цену в корзине, попросить подтвердить |

Резерва нет: остаток проверяется в момент оформления, источник истины — 1С. Если сразу несколько проблем у одной строки, отдаётся первая по порядку таблицы.
