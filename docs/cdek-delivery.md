# Расчёт доставки СДЭК

Серверный модуль использует API СДЭК v2: OAuth и расчёт по коду тарифа. В этом этапе доступен **проверочный расчёт в защищённом API админки**. Витрина и запись стоимости доставки в заказ ещё используют прежний контракт F1. Включение `CDEK_ENABLED` не переключает покупательскую форму и не означает готовность доставки к запуску.

## Подключение

1. Найти Account / Secure password в разделе [«Интеграция» бизнес-кабинета](https://lk.cdek.ru/integration/index). Это API-реквизиты, а не логин и пароль входа в кабинет. Account соответствует `CDEK_CLIENT_ID`, Secure password — `CDEK_CLIENT_SECRET`.
2. Заполнить значения в `.env` **на сервере** или в используемом менеджере секретов. Не отправлять их в чат, не помещать в браузерный код и не коммитить. Шаблоны `.env.example` и `.env.production.example` содержат только пустые поля.
3. Задать `CDEK_ENABLED=1`, явно выбрать `CDEK_ENVIRONMENT=production` для ключей своего договора или `test` для общих тестовых ключей. Хосты фиксированы: `https://api.cdek.ru/v2` и `https://api.edu.cdek.ru/v2`. `CDEK_TIMEOUT_MS` ограничивает каждый запрос, по умолчанию 10 секунд (от 100 до 30000 мс).
4. При отдельном согласованном выпуске перезапустить backend, чтобы он получил окружение. Изменений БД не требуется. Для прямого локального запуска приложение само `.env` не загружает: экспортировать переменные или использовать `node --env-file=.env --import tsx packages/backend/src/index.ts`.
5. Выполнить защищённый запрос ниже и сравнить расчёт с бизнес-кабинетом для **одинаковых** направления, тарифа, веса, упаковки и доп. условий. Общий тестовый аккаунт не учитывает скидки договора, поэтому его суммы не подтверждают боевую цену.

Значения `ADMIN_LOGIN` / `ADMIN_PASSWORD` должны быть настроены: при выключенной админке маршрут отсутствует. По умолчанию СДЭК выключен. Неполные настройки включённой интеграции останавливают запуск с сообщением без секретов.

## Проверочный запрос

`POST /admin/api/cdek/calculate` — Basic-авторизация существующей админки, заголовки `X-FA-Admin: 1` и `Content-Type: application/json`. Ответы имеют `Cache-Control: no-store`. До 20 попыток расчёта на IP в минуту, тело до 32 КиБ, не более 30 упаковок.

Пример **структуры**, не подтверждённые параметры отправки Fashion Avenue:

```json
{
  "tariffCode": 136,
  "fromLocation": { "code": 268 },
  "toLocation": { "code": 44, "address": "Адрес получателя для расчёта" },
  "packages": [{ "weightG": 1200, "lengthCm": 30, "widthCm": 20, "heightCm": 10 }]
}
```

`fromLocation.code` и `toLocation.code` — числовые коды городов **из справочника СДЭК**, не почтовые индексы. `tariffCode` — выбранный код тарифа, доступный по договору. Параметры задаются явно: значения не подставляются из примера. `address` необязателен. Дополнительно поддерживаются `shipmentPoint` и `deliveryPoint` — коды офисов СДЭК; код офиса не заменяет обязательный код города в калькуляторе.

Вес — **в граммах с упаковкой**, размеры — **в сантиметрах**, все четыре значения обязательны и положительные целые. Для нескольких грузомест передаются отдельные упаковки. Это фактические параметры посылки, не сумма количества вещей и не размеры товара без упаковки. Дополнительные услуги (страховка, упаковка СДЭК и другие) в этом этапе не запрашиваются отдельно.

Ответ:

```json
{
  "provider": "cdek",
  "environment": "production",
  "tariffCode": 136,
  "currency": "RUB",
  "deliveryCostKop": 61234,
  "baseCostKop": 50000,
  "periodMin": 2,
  "periodMax": 5,
  "calculatedWeightG": 1200,
  "hasWarnings": false
}
```

Числа приведены только для пояснения формата. `deliveryCostKop` — итог `total_sum` СДЭК в копейках, с НДС и учтёнными СДЭК услугами; `baseCostKop` — базовый `delivery_sum`, который может исключать НДС и услуги. Запрашивается валюта `1` по справочнику СДЭК (RUB, не код ISO 643); ответ в другой валюте отклоняется.

`periodMin` / `periodMax` — диапазон **рабочих дней**, без дня принятия груза; это оценка перевозчика, не обещанный магазином срок передачи. `calculatedWeightG` может отличаться от физического веса из-за объёмного веса. `hasWarnings=true` означает, что СДЭК вернул предупреждения: расчёт требует проверки, в частности при подборе другого офиса. Калькулятор может заменить неподходящий офис ближайшим; успешный расчёт не подтверждает пригодность выбранного ПВЗ для оформления накладной.

Ошибки возвращаются как `{ "error": "CDEK_..." }`:

| HTTP | Код                                 | Значение                                                        |
| ---- | ----------------------------------- | --------------------------------------------------------------- |
| 400  | `CDEK_INVALID_INPUT`                | Не заданы или некорректны направление, тариф, параметры посылки |
| 429  | `CDEK_RATE_LIMITED`                 | Превышен локальный лимит; `Retry-After: 60`                     |
| 503  | `CDEK_DISABLED`                     | Интеграция выключена                                            |
| 503  | `CDEK_TIMEOUT` / `CDEK_UNAVAILABLE` | СДЭК не ответил вовремя или недоступен                          |
| 503  | `CDEK_RATE_LIMITED`                 | Ограничение частоты со стороны СДЭК                             |
| 502  | `CDEK_AUTH_FAILED`                  | Ключи не приняты или недействительный ответ авторизации         |
| 502  | `CDEK_CALCULATION_FAILED`           | Направление/тариф не рассчитаны или СДЭК вернул ошибки          |
| 502  | `CDEK_INVALID_RESPONSE`             | Неполная сумма, неподдерживаемая валюта или некорректный ответ  |

Ошибки авторизации админки, формата JSON и размера тела обрабатываются общей защитой админки (401/403/400/413/415). Ошибки и предупреждения провайдера не выводятся сырыми: они могут содержать данные запроса. При ошибке **нет** подстановки фиксированных 500 ₽, бесплатной доставки или другой приблизительной цены. OAuth-токен хранится только в памяти сервера до истечения срока; параллельные запросы используют одно получение токена. После 401 допускается одно обновление токена.

## Что нужно для покупательской формы

- Подтвердить у магазина место и способ передачи посылок СДЭК, тарифы до ПВЗ/двери, параметры упаковки и включаемые доп. услуги.
- Определить достоверный источник веса/габаритов и правило упаковки корзины; не брать произвольные значения из браузера для окончательной цены.
- Подключить выбор города/ПВЗ и проверку соответствия тарифа выбранному способу доставки.
- Согласовать с Владом изменение публичного API по `docs/api-contract.md`: серверная котировка должна быть связана с корзиной, направлением, офисом, тарифом и сроком действия; браузер не назначает сумму доставки.
- Сохранять параметры и итог расчёта вместе с заказом, повторно проверять изменения до оплаты, получать подтверждение покупателя на новый итог.
- Перевести и гостевое оформление, и ЛК на новый расчёт; обновить конфигурацию чекаута, подтверждение заказа и обмен с 1С. Удалить фиксированный тариф и неподтверждённый порог бесплатной доставки из рабочего сценария.

До выполнения этих пунктов модуль пригоден для проверки интеграции, а **замена доставки в оформлении заказа ещё не завершена**. Накладные, вызов курьера и оплата услуг СДЭК этим модулем не создаются.

## Проверки

`npm test -w @fa/backend -- test/cdek.test.ts test/cdek-admin.test.ts` — детерминированные проверки с подменой только внешнего HTTP-транспорта, без реальных ключей. Общая проверка: `npm run build -w @fa/backend`, `npm run lint`, `npm test`.

Официальная документация: [CDEK API](https://apidoc.cdek.ru/), разделы «Получение токена авторизации», «Расчёт по коду тарифа» и приложение 14. Получение ключей и ограничения тестового контура описаны также на [странице интеграции СДЭК](https://www.cdek.ru/ru/integration/).
