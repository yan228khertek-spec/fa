# Личный кабинет: сервер и API — Implementation Plan

> Исторический план выполненного серверного этапа. Дальнейшие работы и актуальные решения собраны в [сводном плане ЛК, входа и бонусов — v2](2026-11-02-account-loyalty-v2.md).

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Реализовать вход по коду, профиль и работу только с новыми заказами авторизованного покупателя.

**Architecture:** Модули `auth` и `account` внутри существующего Fastify-приложения. PostgreSQL хранит аккаунты, одноразовые запросы входа, ограничения отправки и сессии; хранилище в памяти используется в тестах. Заказы создаются прежним `OrderService`, владелец передаётся сервером из сессии.

**Tech Stack:** TypeScript, Fastify 5, PostgreSQL, node:crypto, Vitest; существующий npm workspace.

## Global Constraints

- Сначала сервер и API ЛК, затем интерфейс — согласовано пользователем.
- Сервиса отправки кодов пока нет — предусмотреть подключение.
- Старые заказы в работе не используем: поиск по телефону, перенос истории и привязка гостевых заказов не реализуются.
- Телефон в профиле пока не редактируется; имя и email редактируются, история заказов при этом сохраняет исходные данные.
- Гостевой сценарий продолжает работать. Новые заказы ЛК создаются через отдельный защищённый endpoint.
- Бонусная система подключается отдельным этапом по `docs/project-plan.md`.
- Секреты, SMS-коды, cookie и тела запросов авторизации не логировать.
- API ЛК документируется отдельно как новое дополнение, существующий согласованный контракт не переписывается.
- Работа в ветке `codex/account-api`; без деплоя и внешних сообщений.

## Задача 1. Одноразовые коды и сессии

**Interfaces:** `SmsSender.send(phone, code): Promise<void>`; `AuthService.requestCode(phone, ip)` возвращает идентификатор запроса; `verifyCode(challengeId, code)` возвращает аккаунт и новый случайный токен сессии; `authenticate(token)` возвращает аккаунт либо null; `logout(token)` отзывает сессию. `AuthRepository` атомарно ограничивает выдачу кодов и потребляет код вместе с созданием сессии.
